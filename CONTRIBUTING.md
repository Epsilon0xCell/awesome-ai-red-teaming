# Contributing

This list is curated, not collected. A pull request that adds one entry which meets the bar is worth more than one that adds twenty that do not.

## The bar for an entry

1. The link is live and points at the canonical source: the project, the standard, or the author's own page. No link shorteners, no mirrors of other people's work, no affiliate links.
2. The description says what the reader will be able to do after using it. "A tool for scanning" fails. "Finds subdomains from certificate logs before you scan anything" passes.
3. Where the format allows, the entry carries its verification: the OWASP test ID it maps to, the fixture it ships, or the check that confirms a result.
4. Security tooling entries must be framed for authorised use, and the resource itself must be lawful to use as described.

## What gets removed

Dead links, abandoned projects that no longer install or run, duplicates of a stronger entry in the same slot, and anything whose description overclaims what the resource does. Removal pull requests with a one-line reason are welcome.

## Order and sections

Entries sit in the section where a practitioner reaches for them during an engagement, ordered by when they are used, not alphabetically. Propose new sections in an issue first, with three entries that do not fit anywhere existing.
